# 编码与规范化滥用

当请求在链路不同环节被**多次、不一致地解码**时，攻击者可以构造"前端看安全、后端看危险"的输入。

## 本目录 PoC

### 双重 URL 解码路径遍历 — `url_double_decode.py`
- 前端 WAF：对请求解码一次，若含 `..` 则拦截
- 后端：再解码一次

双重编码 `%252e%252e%252f`：
1. 前端解码一次 → `%2e%2e%2f`（不含 `..`）→ **漏过**
2. 后端解码二次 → `../` → **真实遍历**

脚本逐行对比四种 payload 在前端/后端的结果。

## 防御要点
- 全链路使用**一致且唯一一次**的规范化解码
- 路径做白名单 + 规范化（解析为绝对路径后做前缀/根目录校验），禁止 `..`
- 不要在 WAF 与后端之间引入解码语义差异
